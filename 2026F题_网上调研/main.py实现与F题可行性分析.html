系统架构（要求 5 合规链路）

合规要点：信号源只接示波器 X 轴 + 装置输入；要求 5 断开装置输入后，信号源频率不得传入/预设——K230 测频 100% 来自摄像头对屏幕的观察。

状态机（Requirement5Controller，9 状态 + FAILED 兜底）

新主流程：START 不发占位 SET → MEASURE_X 收敛 → 必发 $RAMP → 估频后直接精确 $SET → 旋转锁频 → 相位 → 幅度 → HOLD(5s) → DONE。任何斜坡失败一律 FAILED（$FAILED），不回退 v2 扫频。

图像分析流水线（每帧）

性能优化：C 层 find_blobs 预筛（满格包络直接跳过）、mask memoryview 读缓冲、YOLO 隔 2 帧推理 + 锁定后 20 帧复查、显示隔帧。实测 fps≈30~33，推理 29ms，测量 11ms。

RAMP 斜坡测频原理（v3 核心）

  • 原理：F407 切 PA4 DAC 出 1kHz 锯齿（T=1ms）作示波器 Y 轴 → X-Y 显示把输入正弦沿 Y 展开成 x(u)=A·sin(2π·N·u)，N=fx·T_ramp
  • 估频：行质心（ramp_row_centroids）→ 整数周期 DFT 粗估（_ramp_dft_power）→ 黄金分割扫 N 最小化 4 元 LSQ 拟合残差（_ramp_fit_error，sin/cos/直流/线性 4 项）
  • 归整：fx=N×1000 → round(fx/100) 网格 → ratio×（shape=3 时×2）→ 精确 $SET
  • 数学验证：合成 N=12.3 正弦轨迹 → 估计 12.300、质量 0.995（test_ramp_estimate_math 已过）
  • 失败语义：无轨迹 5 帧/档 → 换档 ×3 → FAILED；N 越界 → 换档 ×3 → FAILED；F407 拒绝/ACK 超时 → FAILED

风险 TOP 3 与对策

① 估频归整错档

余辉/摩尔纹导致 N 误差 >0.5 周期 → 归错 100Hz 档。对策：台架用 1k~100kHz 步进 100Hz 全扫实测命中率；命中率 <95% 时改用「RAMP 估频 + ±12 档细扫确认」混合策略（代码保留 RAMP_LOCAL_SWEEP_RANGE_GRID=12 常量可立即启用）。

② 10s 超时

最坏相位粗扫 12 档。对策：实测各档 settle 后压缩 POST_APPLIED_SETTLE_MS（现 80ms）；相位先粗扫一次锁定象限再细扫；必要时 HOLD 首帧即发 $LOCKED 提前上报。超时已设硬断（ERROR_CONTROL_TIMEOUT）。

③ 幅度误差超 0.2div

不同频率点 DDS 平坦性。对策：台架 6 频点×4 档复测幅度表；AMPLITUDE_FINE 闭环已能收敛（误差=+0.00 实测日志），确认收敛后发 $LOCKED 前再等 1 帧稳定即可。

结论

代码层面：main.py 已把要求 5 的闭环走通——合规断耦合、纯摄像头测频、RAMP 粗测频 + 旋转精锁 + 相位/幅度闭环 + 5s 稳定、10s 硬超时、fail-fast 失败语义。数学、状态机、性能三类验证已过，F407 协议与 DAC 输出已编译就绪。

实机层面：可运行性成立，但「估频命中率」「ROI 重标定」「幅度平坦性」三个真机标定项未闭环。按分步台架清单推进（锯齿波形验证 → XY 展开 → 估频命中率全频扫描 → 切 9959 精锁 → 幅度表复测），每步以实测数据回填，10s 预算与 0.2div 幅度误差才有硬保证。
